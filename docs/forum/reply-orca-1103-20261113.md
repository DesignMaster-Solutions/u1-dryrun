Until the slicer asks at Send, the same question can be put to the file itself. The sliced G-code carries what each head was sliced for, in the settings block at the end:

```
; nozzle_volume_type = standard,standard,standard,high_flow
```

I wrote a small text check around that line (Python 3, no dependencies), where you tell it what is installed on heads 1 to 4:

```
$ python3 tools/nozzle_flow.py plate_1.gcode s,s,s,s
the file was sliced for: head 1 Standard, head 4 High Flow
NOZZLE FLOW MISMATCH: head 4 has Standard installed, the file was sliced for High Flow.
```

Exit code 1 on a mismatch, 0 when every head the file uses matches, so it can sit in front of an upload script. Heads the file never selects are ignored. https://github.com/DesignMaster-Solutions/u1-dryrun/blob/main/tools/nozzle_flow.py

Limits: it does not read the printer, the installed list is typed by hand, so it helps a scripted or command-line workflow and not the click on Send that this request is about. Checked on Snapmaker Orca 2.4.1 command-line slices of one four-filament project on macOS, with head 4 set to Standard and to High Flow; nothing was printed, and I have no 2.4.0 file from the Windows GUI to confirm the line looks the same there.

One side note from the same test: when the project has a nozzle type the command line does not know (I first wrote "High Flow" instead of `high_flow`), 2.4.1 slices without any message and the block comes out as a single `nozzle_volume_type = standard`. That is the silent enum substitution described in #1118.
