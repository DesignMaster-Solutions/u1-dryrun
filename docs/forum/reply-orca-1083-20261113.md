I could reproduce this on a small plate with Snapmaker Orca 2.4.1 (command line, macOS), and the cause you suspected holds in an experiment. Since your project was too large to attach, here are files anyone can slice.

**Plate:** two 20 x 20 x 10 mm boxes, 40 mm apart, one per head, stock U1 0.4 nozzle and 0.20 mm profiles, by layer, prime tower off. 50 tool changes after the first layer.

| Slice | First move after `T<n>` | Tool changes that come down to the height already printed before the XY move |
|---|---|---|
| stock tool-change G-code | `G1 Z1.9` while the layer is below 1.9 mm, then `G1 Z<layer>` from layer 10 on | 42 of 50 |
| same, `move_z = 3.0` in the template | `G1 Z3.4` while the layer is below 3.4 mm, then `G1 Z<layer>` from layer 17 on | 34 of 50 |
| lift written as an absolute move | `G1 Z<layer + 1.9>`, XY move, then `G1 Z<layer>` at the part | 0 of 50 |
| stock, prime tower on | XY move to the tower | 0 of 50 |

So the return height is max(layer Z, lift + 0.4): the slicer takes the `Z1.5` of the relative `G91` / `G1 Z1.5` / `G90` lift as an absolute position. Changing the lift to 3.0 moved the layer where the clearance disappears from 10 to 17.

**What removed it in the sliced file:** printer preset, Machine G-code, Change filament G-code, in the by-layer branch replace

```
"G91
G1 Z" + move_z + " F600
G90
";
```

with

```
"G90
G1 Z" + (layer_z + move_z) + " F600
";
```

The real lift before the tool change stays 1.5 mm. At layer 26 the stock file has `G1 Z5.25 F30000` then `G1 X119.398 Y119.398`; the changed one has `G1 Z7.15 F30000`, `G1 X119.398 Y119.398`, `G1 Z5.25`.

This looks like a different path from #1168 (prime tower near the bed edge, which a Snapmaker developer said will be fixed in the December version): here there is no tower and no detour, so that fix may not cover it.

Limits: sliced files only, read as text. I did not run them on the firmware or print them, I did not slice 2.4.0, and the changed template was applied to a copy of the stock profile from the command line, not saved from the Orca window. By object uses the other branch of the template and I did not touch it.
