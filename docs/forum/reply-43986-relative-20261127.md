Update, 27 November: a relative move in the start block is judged when the position is already known.

On 24 November I wrote that this check does not follow relative mode. That was too coarse. The stock purge line is unchanged: G0 X85 Y1 is still 1 mm from the Y limit. What changed is a relative step after an absolute move or a G92.

The head is at Y2 and the next line is G91 then G1 Y-3. The old report stopped at Y2. The file sends the head to Y-1, which is already off the bed, before any head offset. The report now names that line and says it is already past the Y limit, at Y-1.00.

A relative move with no position yet is still skipped. G91 then G1 Y-50 at the top of the stock start block is that case: the macros before it move the head, and I will not invent a coordinate. A macro or G28 in between also clears the position, so a relative move after a home is not applied.

The tests that failed on the old code and pass now are in tests/test_prep_gcode.py (relative step off the bed, G92, and a macro that must forget the position).
